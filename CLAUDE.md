Every v7 document's cross-references resolve to existing v7 documents. No orphan `*_v6` references remain in active v7 documents (the `_superseded_in_v7/` traceability references are the exception). The audit is a `grep` pass across `project/source_documents/v7_completed/`.

The corpus-wide redundancy audit script at `audits/redundancy_audit_v7.py` detects cross-document analytical overlap, duplication-events, and structural-template repetition. ## What to Avoid

- Drafting consolidated documents that lose any Required Thread, primary articulator, or cross-reference from any merged source plan. The union-of-plans gate is mandatory.
- Letting the v7 corpus sit in mid-transition state at phase boundary. Phase 7α's cross-reference repair is bulk and atomic — completed in the same phase as the consolidations.
- Renaming v6 files in `v6_completed/` to v7 names before the consolidation drafting is complete and verified through the union-of-plans gate.
- Treating the v7 capstone as expansion of the v6 capstone. The v7 capstone is the substantive synthesis the v6 capstone anticipates; it operates at different standing (synthesis vs. planning-and-anticipation).
- Performing full-document rewrites in Phase 7δ. Targeted revisions are paragraph or sub-section level only; full rewrites trigger filename change to a new `_v7` ordinal (which the seventh-pass plan does not authorize for Phase 7δ).
- Letting the derivative duplicate the corpus's analytical work. The derivative is condensation-and-accentuation, with the corpus referenced as substrate through reading-paths.
- Deleting (rather than archiving) superseded v6 documents. Archival in `_superseded_in_v7/` is the operational guarantee against substance loss.
- Citing the named scholar previously identified as biographically disqualified (carried forward from v6 What-to-Avoid).
- Citing Anabaptist political theology through individual scholars with biographical-record disqualification (engage the analytical work without the personal citation; carried forward from v6).
- Drafting multiple consequential documents or plans in one response without checkpoint. Per-deliverable checkpoint applies.

## Continue-Plan Protocol

When the user opens a session with **"continue plan"** — or "continue", "resume", "next", or any equivalent — it is a standing instruction to **self-orient and execute the next seventh-pass deliverable** without the user naming any document, file, folder, branch, or phase. Treat "continue plan" as both the instruction and the proceed-confirmation: do not run the Session Start Protocol's step-9 question. Instead, state in one sentence what the next deliverable is, then do it.

Self-orientation algorithm:

1. **Branch.** All v7 work continues on `claude/focused-franklin-AfoMw` unless the user names a different branch. Run `git branch --show-current` to confirm.

2. **Stage detection.**
   - If `project/source_documents/v7_completed/` does not exist or contains fewer than 35 files → **Phase 7α** is incomplete. Within 7α: if the redundancy audit report does not exist → run the audit; if the two consolidation plans do not exist → author them; if the two consolidated documents do not exist → draft them; if cross-reference repair has not landed → run the repair pass; if the superseded archive is not populated → archive the nine superseded documents.
   - If `v7_completed/` contains 35 files but `outputs/v7_audits/Corpus_Tension_Catalog_v7.md` does not exist → **Phase 7β**: corpus-wide tension-identification read.
   - If the tension catalog exists but `v7_completed/XIV.01_Capstone_Synthesis_v7.md` does not → **Phase 7γ**: v7 capstone synthesis.
   - If the v7 capstone exists but `outputs/v7_audits/Phase_7delta_Revision_Log.md` does not exist (or exists but does not record every punch-list item as landed or explicitly deferred) → **Phase 7δ**: targeted revisions.
   - If targeted revisions are complete but `outputs/v7_derivative/` does not exist or is empty → **Phase 7ε**: public-facing derivative.

3. **Execute.** Read the relevant plan; draft to the named output path; run the audits; commit; push.

4. **Report and scope.** One "continue plan" completes one deliverable, then gives the per-deliverable checkpoint and names the next deliverable. The user may widen the scope explicitly ("continue plan through Phase 7γ", "continue until an issue arises"); honor the stated width.

"Continue plan" does not override the Ambiguity Handling section: if the next step is genuinely ambiguous, a cross-referenced upstream document is missing, the redundancy audit surfaces consolidation candidates beyond Cluster A and Cluster B (which require user decision since moderate scope was authorized), or a planning specification contradicts a source, stop and escalate.

## Ambiguity Handling

The plan is the canonical specification. If a plan specification is ambiguous, the source files contradict the plan, a cross-referenced upstream document is absent, the union-of-merged-plans operation surfaces a Required Thread that the consolidation cannot accommodate without splitting, or the redundancy audit identifies consolidation candidates beyond the moderate-scope Cluster A and Cluster B, **stop and ask the user immediately**. Do not guess. Do not pick the most likely interpretation. Do not silently expand consolidation scope.

The escalation format:

```
## Ambiguity — <deliverable id>

Plan specification: <quote the relevant section>

Conflicting condition: <quote source file, cross-reference, or audit finding>

Possible readings:
1. <reading A and what deliverable it would produce>
2. <reading B and what deliverable it would produce>

My recommendation: <which reading and why, briefly>

Awaiting your resolution before proceeding.
```

Wait for user response. Do not proceed until resolved.
